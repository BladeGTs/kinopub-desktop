# KinoPub Desktop

Неофициальное настольное приложение [KinoPub](https://kino.pub) для Windows, Ubuntu и macOS на Electron. Для просмотра нужен аккаунт KinoPub с действующей подпиской и доступ к серверам сервиса.

Проект: [BladeGTs/kinupub-desktop](https://github.com/BladeGTs/kinupub-desktop).

![Интерфейс приложения](docs/screenshots/home.jpg)

## Возможности

- Каталог фильмов и сериалов, поиск, фильтры, закладки и история просмотра.
- Переключение качества, озвучки и субтитров; переход к следующей серии.
- Управление мышью и клавиатурой, кнопки возврата и паузы в плеере.
- Полноэкранный режим окна, двойной клик по видео и скрытие курсора при просмотре.
- Системный или пользовательский HTTP/SOCKS5-прокси, в том числе для видео.
- Сохранение авторизации и настроек между запусками.

Интерфейс сохраняет компоновку исходного телевизионного клиента и масштабируется под размер окна. При другом соотношении сторон возможны чёрные поля.

## Установка

Готовые установщики публикуются в [Releases](https://github.com/BladeGTs/kinupub-desktop/releases) после успешного выпуска версии.

| Система | Архитектура | Пакет |
| --- | --- | --- |
| Windows | x64 | `.exe`, установщик с выбором папки |
| Ubuntu / Debian | amd64 (x64) | `.deb` |
| macOS, Apple Silicon | ARM64 | `.dmg` и `.zip` |

**Windows:** скачайте `.exe`, запустите установщик и откройте KinoPub из меню «Пуск» или ярлыка. Значок приложения — буква «К».

**Ubuntu:** скачайте `.deb` и установите через менеджер приложений либо командой из каталога с файлом. Пример для версии `1.4.12`:

```bash
sudo apt install ./KinoPub-1.4.12-ubuntu-x64.deb
```

Подставьте имя скачанного файла. Внутренняя версия Debian-пакета совпадает с версией приложения, без суффикса `-1`.

**macOS:** скачайте `.dmg` из Releases, откройте его и перенесите KinoPub в «Программы». Сборка рассчитана на Apple Silicon; Intel-версия в текущем workflow не собирается. Также доступен `.zip` с приложением.

Пакеты пока не имеют настроенной подписи Windows или Developer ID / нотариализации Apple. При установке система может запросить разрешение на запуск.

**Вход:** приложение показывает код устройства. Откройте указанный адрес KinoPub в браузере и подтвердите код в своём аккаунте. Если требуется прокси, его можно настроить на экране входа.

Для обновления установите новый пакет поверх предыдущего. Автоматическое обновление пока не реализовано. Установщикам не нужны Node.js, pnpm или webOS CLI.

## Управление

| Действие | Управление |
| --- | --- |
| Навигация | Мышь либо стрелки и Enter |
| Возврат / закрытие открытой панели | Кнопка «Назад», Esc или Backspace вне поля ввода |
| Пауза / продолжение | Кнопка плеера, пробел или одиночный клик по свободной области видео |
| Полный экран / оконный режим | Двойной клик по видео, кнопка полного экрана или F11 |
| Полный экран на macOS | Также Ctrl+Cmd+F |
| Показать управление и курсор | Подвигать мышью |
| Закрыть фильтр, список или панель | Кликнуть по свободной области вокруг него |

Кнопка «Назад» отсутствует на главной странице. В плеере она сначала закрывает открытую панель, затем возвращает к предыдущему экрану. Одиночный клик по видео обрабатывается с небольшой задержкой, чтобы отличить его от двойного. После нескольких секунд без движения курсор и управление скрываются.

## Прокси

Откройте **Настройки → Прокси** или **Настроить прокси** на экране входа.

- **Системные настройки** — использовать настройки прокси операционной системы.
- **Без прокси** — подключаться напрямую.
- **Свой прокси** — указать HTTP- или SOCKS5-сервер, имя/IP и порт отдельно, без префикса `http://` и пути.

HTTP-прокси поддерживает логин и пароль; SOCKS5 — без авторизации. Пароль сохраняется через защищённое хранилище системы. На Linux для сохранения пароля требуется доступное системное хранилище ключей; без него можно использовать прокси без пароля.

Прокси применяется к каталогу, изображениям и видео. После сохранения повторите запрос или заново откройте видео: существующие сетевые соединения закрываются. Локальные адреса компьютера обходят прокси.

## Требования для разработки и сборки

- Git.
- [Node.js](https://nodejs.org/) 24; в проекте указана версия `24.18.0`.
- [pnpm](https://pnpm.io/) `10.15.0`, указан в `app/package.json`.
- Интернет для установки зависимостей и загрузки Electron / инструментов упаковки.
- Для локальной сборки установщика рекомендуется соответствующая ОС: Windows, Linux или macOS. Без локальной целевой ОС используйте GitHub Actions.

Для desktop-версии не нужны телевизор, LG Developer Mode и webOS CLI. Поддержка видеокодеков зависит от Electron и системы; воспроизведение необходимо проверять на целевой платформе.

Проверьте Node.js и установите нужную версию pnpm:

```bash
node --version
npm install --global pnpm@10.15.0
pnpm --version
```

Клонируйте проект и установите зависимости:

```bash
git clone https://github.com/BladeGTs/kinupub-desktop.git
cd kinupub-desktop/app
pnpm install --frozen-lockfile
```

## Запуск для разработки

Все команды этого раздела выполняются из каталога `app`.

```bash
pnpm desktop:dev
```

Запускает Vite и окно Electron с обновлением интерфейса при изменениях. Для запуска собранного интерфейса в Electron:

```bash
pnpm desktop:start
```

Для проверки только веб-интерфейса в браузере:

```bash
pnpm dev
```

Адрес Vite: `http://localhost:5173`. Desktop-функции, например системный прокси, доступны в Electron. Профиль разработки отличается от профиля установленного приложения.

## Локальная сборка установщиков

Перед выпуском задайте единую версию из **корня репозитория**:

```bash
node scripts/set-release-version.mjs 1.4.12
```

Скрипт обновляет `app/package.json`, `app/electron-builder.yml` и `app/webos/appinfo.json`. Затем перейдите в `app`.

**Windows x64**, сборка на Windows:

```bash
pnpm desktop:build:win --x64 --publish never
```

**Ubuntu amd64**, сборка на Linux, только `.deb`:

```bash
pnpm build
pnpm exec electron-builder --linux deb --x64 --publish never
```

Для одновременной сборки `.deb` и AppImage:

```bash
pnpm desktop:build:linux --x64 --publish never
```

**macOS ARM64**, сборка на Mac с Apple Silicon или облачном macOS runner:

```bash
pnpm desktop:build:mac --arm64 --publish never
```

Результаты находятся в `app/release/`. Эта папка, зависимости и локальные настройки не включаются в Git.

Дополнительные команды:

```bash
pnpm desktop:pack     # распакованное приложение для текущей ОС
pnpm check            # TypeScript, линтер, форматирование и все тесты
pnpm test:electron    # тесты Electron и подготовки версий релиза
```

## Сборка через GitHub Actions

[Страница Actions](https://github.com/BladeGTs/kinupub-desktop/actions).

### Ручная сборка, включая macOS ARM64

1. Откройте **Actions → Desktop builds**.
2. Нажмите **Run workflow** и выберите ветку, обычно `main`.
3. Дождитесь завершения сборок Windows x64, Ubuntu x64 и macOS ARM64.
4. Откройте запуск и скачайте установщики в разделе **Artifacts**.

Сборка macOS выполняется на облачном Mac GitHub. Собственный Mac для этого не нужен. Этот workflow использует версию из конфигурации проекта и не создаёт GitHub Release.

### Автоматический релиз по тегу

Workflow **Release** запускается при отправке тега `vX.Y.Z`, например `v1.4.12`.

Он:

1. Берёт версию из тега и запускает проверки.
2. Собирает Windows x64 `.exe`, Ubuntu amd64 `.deb` и macOS ARM64 `.dmg` / `.zip` на соответствующих runner.
3. Проверяет версию `.deb` и устанавливает его на Ubuntu runner; у приложения macOS проверяет версию и архитектуру ARM64.
4. После успешного завершения всех трёх сборок публикует GitHub Release с установщиками и `SHA256SUMS`.

macOS собирается на облачном Mac GitHub одновременно с Windows и Ubuntu. Дополнительный токен для публикации не нужен: используется встроенный `GITHUB_TOKEN` с разрешением на запись содержимого репозитория в задаче публикации.

Сначала закоммитьте и отправьте изменения. Затем из корня репозитория создайте новый тег и отправьте его:

```bash
git tag -a v1.4.12 -m "Release 1.4.12"
git push origin v1.4.12
```

Либо в Bash / Git Bash используйте вспомогательный скрипт, который обновит версии, создаст коммит при необходимости, тег и отправит изменения:

```bash
bash scripts/release.sh 1.4.12
```

Скрипт требует чистого рабочего дерева. Каждый выпуск получает новый номер. Версия в теге автоматически применяется при сборке, поэтому вручную менять конфигурацию перед отправкой тега необязательно. Повторный запуск workflow обновляет вложения существующего релиза.

Готовые файлы появляются в [Releases](https://github.com/BladeGTs/kinupub-desktop/releases). Если workflow завершился с ошибкой, откройте упавшую задачу в Actions: релиз создаётся только после успешных проверок и сборок.

## Структура проекта

| Путь | Назначение |
| --- | --- |
| `app/src/` | React-интерфейс, сервисы API и плеер |
| `app/electron/` | Окно Electron, preload, прокси и тесты |
| `app/electron-builder.yml` | Форматы установщиков, значки и версия desktop-пакета |
| `app/webos/` | Унаследованные ресурсы интерфейса и метаданные версии |
| `.github/workflows/` | Проверки, ручные сборки и релизы |
| `scripts/` | Подготовка версии и вспомогательные скрипты |
